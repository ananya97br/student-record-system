# NF-005 Accessibility and Usable Role Navigation

## Automated coverage

- `TC-UX-01` (`test_TC_UX_01_accessible_portal_evidence` in
  `tests/test_requirements.py`) checks selected portal markup, including the
  main-content landmark and table column headers. It is a focused markup
  assertion, not a complete accessibility audit.
- `TC-UX-02` (`test_TC_UX_02_portal_navigation_is_role_specific` in
  `tests/test_requirements.py`) checks that student, faculty, and admin
  dashboards show role-specific navigation and that representative
  cross-role portal paths redirect.
- Browser cases `test_TC_UX_01_login_and_representative_pages` and
  `test_TC_UX_01_axe_login_page` are documented in
  [`e2e/test_portal.py`](../../e2e/test_portal.py). They require Playwright,
  Chromium, and (for axe-core) browser network access.

## Manual review still required

The automated checks do not establish full accessibility conformance or
usability. Review the running application with keyboard-only navigation,
visible focus, logical focus order, screen-reader labels and announcements,
text and UI contrast, zoom/reflow, and error handling. Check role navigation
with representative accounts and confirm both that permitted sections are
discoverable and that restricted paths remain inaccessible. Record the date,
browser/assistive technology, tested roles, findings, and remediation status
before marking the manual acceptance criterion complete.
