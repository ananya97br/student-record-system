# SR-004 Sensitive Security Alerts and Export Monitoring

## Documented behavior

- Five failed login attempts lock the account, create an `ACCOUNT_LOCK` audit
  event and a high-severity `REPEATED_LOGIN_FAILURE` alert, and send a
  notification.
- A denied authorization attempt creates an `AUTHORIZATION_DENIED` audit event
  and a medium-severity `UNAUTHORIZED_ACCESS` alert.
- Report exports create `REPORT_EXPORT` audit events. At least five exports by
  the same actor within five minutes create a high-severity `BULK_EXPORT`
  alert.
- Admin and system-admin roles can list security alerts and resolve them. The
  API's list is limited to the newest 500 alert records.

## Review procedure

Review `GET /api/auth/security-alerts` together with
`GET /api/reports/audit/list`. Investigate high-severity account-lock and
bulk-export alerts, correlate events with the actor and business purpose, and
preserve evidence according to the incident process. Resolve reviewed alerts
through `POST /api/auth/security-alerts/<id>/resolve`; record who reviewed
them and the outcome outside the application as required by local policy.

The application supplies records and an administrative API, not a configured
on-call schedule or centralized monitoring integration. Production operators
must separately arrange continuous review, escalation, and retention.
