## Update procedure for subsequent sprints

1. Review requirements and acceptance-criteria changes alongside the sprint's
   changed tests.
2. Keep test IDs consistent between requirement documentation, test method
   names, and the automated traceability index.
3. Update the matrix's evidence description and mark manual, browser,
   infrastructure, and performance checks that remain outstanding.
4. Record test command, result, commit, date, and environment for each published
   run. Keep generated CI reports with their run artifact rather than reusing
   results from a different commit.
